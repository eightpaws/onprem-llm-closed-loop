# Чек-лист закрытого контура

Порядок важен: сначала подготовка на машине с интернетом, потом перенос, потом проверка. Если сделать наоборот, стенд будет пытаться достать модель из сети и молча падать.

## 1. Подготовка (на машине с доступом)

- [ ] выбрать модель под задачу и под память карты: `docs/model-selection.md`
- [ ] скачать образы: `docker pull ollama/ollama:0.40.16`, собрать `deploy/Dockerfile.llamacpp`
- [ ] скачать веса GGUF и/или теги Ollama в каталог, который поедет на стенд
- [ ] зафиксировать версии в `deploy/env` и в описании поставки

## 2. Перенос (без интернета)

- [ ] скопировать каталоги моделей на стенд
- [ ] `docker load` для образов либо локальный registry внутри контура
- [ ] проверить, что `MODELS_DIR` и `GGUF_DIR` указывают на перенесённые каталоги

## 3. Запуск

- [ ] `docker compose -f deploy/docker-compose.yml up -d`
- [ ] `docker compose ps` показывает оба сервиса в состоянии running
- [ ] `curl http://127.0.0.1:11434/api/tags` возвращает список моделей

## 4. Проверка изоляции

- [ ] `./scripts/verify-isolation.sh` завершается с итогом «контур закрыт»
- [ ] отдельно: `docker compose exec ollama sh -c 'curl -m 5 https://api.openai.com'` падает по таймауту
- [ ] DNS внутри контейнера не разрешает внешние имена

## 5. Замер и фиксация результата

- [ ] `./scripts/bench.sh <модель>` пишет JSON в `results/`
- [ ] замер повторён минимум дважды, оба результата сохранены
- [ ] в отчёте указано: карта, драйвер, версия движка, контекст, квантование KV

## 6. Что положить в отчёт руководству

- [ ] скорость в токенах в секунду на типовом запросе
- [ ] что не влезает в память и какой ценой обходится (контекст, размер модели)
- [ ] чем подтверждается изоляция: вывод скрипта, дата, кто запускал
- [ ] что осталось непроверенным
